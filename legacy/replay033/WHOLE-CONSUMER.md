# Private whole Hub1 source/coinflow reconciliation

This is an independent private evidence pipeline, not production financial
admission, an importer, a ledger repair, or public promotion. A prepared program
and passing unit tests are NOT whole financial acceptance. Each original source
must actually finish and pass its own complete financial proof first.

## Sole owned private supervisor

`run_whole.py --directory <private-controller> --repo <frozen-signed-worktree>
--canonical-boundary <accepted-500000-directory> --terminal-seal <accepted-tail-seal>`
holds a global single-owner lock. It leaves every original Job/Pod/claim alone.
It starts each of the three private profile drivers once, immediately after its
real original source and original shell completion stamp exist. Waiting protects
unfinished financial records from being accepted as complete; the original native
recorders clear that condition, not an approval or a model. The source recording
clock is not a whole-financial finish forecast.

The controller persists its PID, actual child PIDs, 30-second heartbeat, source
recording heights, independently checked financial heights and actual exits.
Transport failures are unknown, not healthy or complete, and retry next tick.
An original `failed.private` is fatal even after native target. An empty or missing
shell integrity stamp still waits. Bulk captures share a lock and subtract live
siblings' future workspace reservations, protecting retained data and the reserve
without serializing financial proofs or truncating sources.
Restarting the SAME controller directory adopts completed actual exit/seal files
or a still-live supervisor whose exact command and private path match. It never
blindly duplicates an existing attempt. A missing supervisor without an actual
exit is a diagnostic failure, not permission to repeat a financial proof. All
attempts and any still-live children remain retained on controller failure.

## Complete original profiles

`run_closed_profile.py --first 1|200001|400001 --directory <NEW-private-attempt>
--repo <signed-clean-worktree>` is a one-shot supervisor. It never polls, dispatches,
changes, pauses, restarts or deletes an original Job. An unfinished source is
refused before large capture. Existing source identities, images, actual native
runtime binaries, source targets, cache bytes and frozen opening manifests remain
strict. Workspace headroom includes measured compressed inputs, another copy,
the existing private-output allowance and retained-data reserve.

The steps are:

1. `capture_closed.py` captures the original source's full closed gzip bytes.
   Native target AND verified-through must equal the actual original target,
   with the exact successful next-header status. Coin and native-history streams
   both require their actual final markers, exact raw byte counts/hashes, a valid
   gzip close, and no trailing bytes, records or concatenated members. Every
   current/previous/next raw block/results member and genuine genesis is retained.
   Closed files are read through the EXISTING pinned retained legacy-Hub1 Pod's
   shared mounts using only dd/stat/tar/hash and a fixed read-only existence probe. No new Pod, PVC or source
   mutation is needed, and no exec into a completed producer is attempted. The
   original completed manifest, recorded binaries, source binding, gzip-validation
   completion stamp and original producer UID/container remain independently bound.
   The local full-stream digest must match the original producer's completed
   manifest. Whole-cache readback hashes batches, not one process per file, and
   timeouts scale with measured stream bytes and exact member counts.
2. Build/test the helper from the clean signed RUN-START source. Retain every
   compiled Go source pin and every Python source digest from that same commit. No historical block or payout keeper is executed by the helper.
3. `consume_closed.py` uses the complete streaming phase/journal consumer with
   exact signed transaction, payer/fee vector and original staking message
   bindings, bank amounts, native principal/share before/after, all nine stores,
   attempted/aborted writes, dispositions, exact mint and liabilities, full ABCI
   results, and independently reproduced IAVL roots at every height. The final
   normal native-history marker supplies its ORIGINAL unexecuted next header,
   not an invented execution or state. Every final raw store anchor must agree.
4. Bind actual negative controls to that full source and helper. Rehash original
   source streams, all captured raw cache members, all frozen normal-opening
   members and original binaries AFTER the financial proof. Original Pod/container
   identities and zero restarts must remain unchanged.
5. `seal_closed.py` requires actual exit 0, exact independent phase/height/tx
   counts, complete source closure, actual controls, post-proof source preservation,
   compiled source pins, and clean signed code. HEAD must still equal the actual
   run-start commit and every Python digest must still equal that start's signed
   bytes. A newer signed HEAD cannot retroactively name older executed code.
   Every compressed source, raw cache member, opening member, metadata file and
   source tar is in the seal inventory, not just its manifest. Failed attempts
   are preserved.

No bounded receipt can be adapted into a closed profile by changing a flag or
adding a footer. The source/profile schema, actual producer status, terminal
markers, all final stores, and independent native coverage all have to agree.

## Final assembly, no historical reruns

`reconcile_whole.py --config <private-json> --repo <signed-source-repo>
--receipt <NEW-private-result>` accepts a config with exactly:

- `profiles`: three `{path, sha256}` complete-profile seals, in actual order
  1..200000, 200001..400000, 400001..500000.
- `terminal_seal`: the existing accepted terminal-fifteen release seal.
- `canonical_boundary`: the existing accepted canonical-500000 fixture directory.

The assembler verifies signed code and artifact pins, independent native counts,
all-nine-store normal checkpoint joins at 200000 and 400000 BY STORE NAME (not
random Go map serialization order), the canonical 500000
application root, and the accepted 500000 tail opening. It reuses the fixed
accepted terminal component and canonical export/genesis proof without executing
an old export, payout, block, terminal proof or a fictitious 500016. The retained
500001..500015 source is a SEPARATE closed-native-reference component, never the
next chain's opening. Zero-height validation payouts are not historical income.
Final byte readback heartbeats every 1000 artifact references. Immutable hashed
configs can be retried without overwriting prior configs. A completed whole
result is independently read back and adopted on restart, never turned into a
failure merely because its files exist.

Only actual complete seals can yield 500015 reconciled historical heights. Even
that private historical-source result keeps production import/public promotion,
financial admission and books/tax acceptance false. Those are different actions
with their own accounting requirements and Dan's production authorization.
